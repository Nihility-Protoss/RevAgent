# VM 保护与重度混淆样本静态分析方法论

## 适用条件
arch_detection.code_frameworks 含 vm_protected，或 packer_protector 命中 VMProtect 类保护；
Phase 3 中发现"反编译失败 + 函数体积巨大 + 控制流平坦化"的函数时也应按本指南处理。

## 核心原则：不做指令级还原
VM 保护样本的完整指令集逆向成本以月计，对威胁情报提取既不现实也无必要。正确路线：
静态识别 VM 架构 → 提取硬编码常量 → 归纳行为模式 → 在 I/O 边界动态验证。

## 识别特征（函数级证据）
- 函数体积异常：按 size 排序关注 Top 5%（>3KB 即值得怀疑），反编译失败（disassembly-fallback）者优先。
- CFG 呈扁平放射状：单一入口 + 大量放射分支，函数内 loc_ 标签 >50 个。
- 典型汇编骨架：外层循环（cmp + jnb 退出）→ 读"字节码"（movzx 取缓冲区字节）→ 嵌套比较分发 → 写回结果 → 跳回循环头。

## OLLVM 平坦化 vs VM 解释器
- OLLVM 平坦化：通常只有 1 个状态变量（分发索引），分支目标对应原基本块，数据流与原程序一致。
- VM 解释器：2 个以上状态变量（VM PC + 边界 + 数据索引），存在独立的字节码缓冲区，分支目标是"指令处理例程"。

## 静态分析路线（四步）
1. **确定 VM 边界**：找循环退出条件（cmp/jnb），记录每轮处理的数据量（如 16/25/70 字节）。
2. **提取硬编码常量**：栈上 `mov [rsp+xx], imm` 按小端重组为密文种子；收集 64 位立即数中的高熵魔数（排除镜像基址附近的地址值）。
3. **定位全局状态变量**：函数入口读 .data 相邻 QWORD 的静态值常为全 0xFF（未初始化标记，无分析价值，真实值必须动态取）。
4. **归纳写回模式**：顺序解码（写回+递增）、状态改变、多轮处理、非线性跳跃、完全重置五种；识别 and/sub/add/lea 算术原语即可，不逐条还原。

## 静态能做 / 不能做
- 能：识别 VM 架构层次、提取密文与魔数、归纳写回模式、定位关键 I/O 点。
- 不能：确定状态变量初始值、完整解密（路径依赖初始状态会爆炸）、绕过反调试未执行的代码。

## 断点策略（I/O 边界动态验证，最关键）
- 字符串操作边界：lstrcpyW / lstrcatW / memcpy 等 VM 出口下断，直接捕获解密后的 C2、配置明文。
- 网络请求边界：WinHttpSendRequest / WSASend 调用前下断，观察 VM 构造的请求包。
- 标准算法边界：VM 前后常接 RC4/AES/Base64，在 RC4 KSA 完成后、AES 解密后取中间明文。
- VM 入口下断：读取动态初始化的 VM PC 与边界值。
- 避坑：不要步过事件循环（Sleep/epoll 阻塞会卡死）；心跳间隔调大避免干扰单步；函数未执行先排查环境检测型反调试。

## 置信度规则
- high：汇编骨架 + 状态变量布局 + 边界条件等结构性证据齐备。
- medium：仅函数体积 + 反编译失败等间接迹象。
- low：仅加壳字符串（VMProtect/Themida 字样），需函数级证据佐证。
